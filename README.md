# NikaS Water Treatment для Home Assistant

Самостоятельная панель **«Водоподготовка»**: фильтры, умягчитель «Ёлка», соль, регенерации и GH. Выделена из [ha-water-accounting](https://github.com/NikaSir/ha-water-accounting) с сохранением расчётов и данных. Подготовленная версия **0.2.0-beta001**. Минимальная заявленная версия Home Assistant — **2026.10.4**.

| Вкладка | Назначение |
|---|---|
| Обзор | Состояние трёх узлов, ресурс, соль, последняя регенерация и GH, ближайшее обслуживание |
| Фильтры | Сроки и ресурс магистрального фильтра и БАРЬЕР, даты замены, настройки |
| Ёлка | Досыпка и проверка соли, обслуживание бака, регенерации, параметры для учёта |
| Жёсткость | GH-пробы до/после умягчителя и после БАРЬЕР, исходные капли и пересчёт в °Ж |

Маршрут `/dashboard-water-treatment`; самостоятельный пункт бокового меню HA. Учёт давления, расхода и водомеров остаётся в `ha-water-accounting` на `/dashboard-water`. Для работы водоподготовки приложение учёта не требуется; исходный питьевой водомер читается прямо из HA.

## Обзор

Новая панель открывается на вкладке «Обзор»; после выбора другой вкладки сохраняется последний открытый раздел. Три карточки показывают данные из существующих журналов и настроек:

- **Магистральный** — м³ после замены и остаток ресурса по выбранному правилу: объём, срок или оба критерия.
- **Ёлка** — последняя записанная регенерация, расчётная масса соли и последний GH именно после умягчителя с датой пробы.
- **БАРЬЕР** — отдельный срок каждого из трёх картриджей.

Баннер обслуживания учитывает срочные состояния и ближайшие известные сроки. Нажатие на карточку или баннер открывает соответствующий раздел. Неизвестные значения показываются прочерком; расчётный ноль соли предлагает проверить запас и не означает подтверждённый пустой бак. При ошибке чтения или потере связи обзор убирает устаревшие значения и восстанавливается после успешного чтения.

Иллюстрации поставляются внутри интеграции. Обзор использует тему HA, фиксированную шапку и нижние вкладки; обновление данных сохраняет карточки, прокрутку и черновики форм.

## Установка и переход

1. При переходе со старой объединённой версии сначала обновите «Учёт воды» до **0.3.0-beta001** или новее и перезапустите HA.
2. После согласованной публикации добавьте этот репозиторий в HACS как **Integration**, установите пакет и перезапустите HA.
3. Добавьте интеграцию **NikaS Water Treatment** в настройках устройств и служб.
4. Сверьте перенесённые даты, события и параметры.

[Полная инструкция перехода, резервного копирования и отката](docs/WATER_SPLIT_MIGRATION.md).

## Сохранение и безопасность

Настройки и журналы сохраняются в HA (`water_treatment.filters`). При первом запуске прежний `water_accounting.filters` однократно копируется целиком вместе с ревизией; исходный файл остаётся архивом. Импорт повторно не выполняется. В новом хранилище остаётся исходный снимок для восстановления. Активная старая версия блокирует импорт/запись, а ошибка диска или повреждённые данные не подменяются пустым журналом.

API `water_treatment/filters` требует авторизации HA; чтение доступно пользователям, изменения — администраторам. Конфликты одновременных изменений проверяются ревизией. Панель не управляет клапаном, водой или автоматизациями.

## Расчёты

- Профиль старой «Ёлки»: 8 л смолы и 1 кг соли/цикл **предварительны**, 1,20 м³ — временно заданный объём. При переносе сохранённые значения и основания не меняются.
- Фактическая масса соли и оценка по дозе показываются отдельно. Очистка бака задаёт новый исходный запас; удалённая соль учитывается отдельным событием.
- GH: НИЛПА, проба 5 мл; капли = °dGH; °Ж = °dGH × 0,3566. Только явное применение пробы после умягчителя меняет расчёт срока БАРЬЕР.
- Магистральный фильтр использует питьевой водомер; полив исключён. Отсутствие водомера означает неизвестный расход. Вода регенерации повторно из показаний не вычитается.

[Технические основания и ограничения](docs/WATER_TREATMENT_NOTES.md).

## Разработка и проверка

```bash
npm run build
npm run check
```

`npm run preview` открывает локальный предпросмотр с явно тестовыми данными и без записи в HA. Для браузерной проверки установите Playwright и Chromium в среде разработки, затем выполните `npm run check:browser`. Переменная `OVERVIEW_BROWSER_PATH` позволяет указать существующий Chromium; `OVERVIEW_BROWSER=webkit` выбирает установленный WebKit. Сценарии проверяют реальный собранный frontend на семи размерах телефона/планшета/настольного экрана (от 320×640 до 1440×900), обе темы, переходы, потерю связи, сохранение черновика и точечные обновления.

Автономный frontend без runtime-импортов; существующая оболочка NikaS, масштаб 75–200%, сохранение черновиков и защита от потери нажатий во время обновления. Проверки переноса используют разные ключи хранилищ, ошибки записи и повторные старты. Браузерная и приёмка на установленном HA фиксируются отдельно от локальных тестов и CI.
