# Water Treatment Overview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add the approved overview tab using existing treatment data and three local illustrations.

**Architecture:** A pure model formats backend snapshots into display state; static overview markup is point-patched by the panel. Existing detail views and all journal writes remain unchanged.

**Tech Stack:** Vanilla JavaScript custom element, CSS, Home Assistant Python metadata, Node test runner, Playwright verification.

**Spec:** `docs/superpowers/specs/2026-11-07-overview-design.md`

## Global Constraints

- Four tabs in order: overview, filters, softener, quality.
- Version `0.2.0-beta001`, one deterministic JS bundle, local versioned assets.
- Preserve the NikaS fixed shell and existing form drafts.
- No hardcoded readings, inferred salt baseline, successful-softening claim or physical commands.

## Review Focus

- Zero remaining resource must appear due; null must appear unknown (task 1).
- Inlet/BARRIER GH or a same-day pre-cycle sample must not confirm softening (task 1).
- Failed read/reconnect must clear stale success and recover in place (task 2).
- Narrow phones and long overdue text must retain readable labels and reachable navigation (task 2).
- Polling/navigation must preserve mounted nodes, scroll and drafts (task 2).
