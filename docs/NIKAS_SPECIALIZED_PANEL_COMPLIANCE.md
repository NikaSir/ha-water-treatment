# Соответствие панели «Водоподготовка»

Подготовленная версия интеграции/UI: `0.1.0-beta001`. Источник — выделение из ha-water-accounting `7ca543b19922e3a0d8f40ebfc81270145a15b5a0`. Проверено локально 06.11.2026.

| Область | Результат / предел |
|---|---|
| Оболочка NikaS 2.2 | Канонический закреплённый source kit; автономный детерминированный bundle, отдельный компонент/маршрут |
| Вкладки и формы | 3 постоянные вкладки; регрессионные тесты сохранения, конфликтов, защиты черновиков и фона |
| Перенос | Целевой файл, повторные запуски, архив, ревизии, все типы записей, ошибка диска и старый writer проверены тестами |
| Надёжность диска | Атомарный Store с проверкой действительных байтов после записи; повреждение и ранее оставленные .corrupt.* не считаются новым пустым журналом |
| Права | Чтение авторизованным пользователям; изменения администраторам, с проверкой ревизии |
| Источники | Только исходный питьевой счётчик; нет управления клапаном, автоматизациями или водой |
| Геометрия и touch в браузере | GAP: локальный движок не установлен, загрузка недоступна, облачный браузер не имеет доступа к localhost |
| Установленный HA/HACS/iPhone | GAP: установка, перенос живых данных, перезапуск и физическая приёмка ещё не выполнялись |

Минимальная заявленная HA: **2026.10.4**, baseline API, прочитанный при проверке. [Официальная реализация Store](https://github.com/home-assistant/core/blob/2026.10.4/homeassistant/helpers/storage.py) проверена: стандартный Store может возвращать None после переноса повреждённого JSON в .corrupt и логировать WriteError без исключения. Поэтому чтение журнала проверяет действительный файл в executor, запись включена с atomic_writes и подтверждается чтением диска.

Локальный PASS не означает доставку HACS, проверку живого оборудования или успешный перенос фактического журнала пользователя.
